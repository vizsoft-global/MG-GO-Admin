1. Requirements delivered

The client asked for three things. This is what each one turned into.

1.1 In-depth attendance-based scoring

Shift, overspeed, on-time delivery, and related compliance signals.

# Requirement Where it lives
1.1 Compliance is no longer one opaque number — it is seven named components: Punctuality, Duty ratio, Within SLA, Speed, Zone & range discipline, GPS, Conduct /performance → Period tab → Components toggle
1.2 Each component has an admin-editable weight /performance/settings → Compliance components
1.3 On-time delivery = pickup → delivered under a configurable minutes threshold, global with per-zone and per-partner overrides /performance/settings → SLA minutes
1.4 A component with no data is dropped and the rest re-weighted — never scored zero Shown as — with a tooltip in the table
1.5 Lateness is no longer a cliff (was: 1 minute late = same score as 90 minutes late) and is no longer penalised twice Punctuality component
1.6 Per-day component breakdown visible per driver per day /attendance → expand the Compliance column
1.7 Nightly rollup at 02:00 so historical trends are queryable /api/cron/performance-rollup
1.8 Every weight change is audit-logged with before/after /settings/logs

1.2 Operations rating of behaviour, appearance and others

# Requirement Where it lives
2.1 Each team rates multiple named criteria, not one number /performance → click a driver → rating panel
2.2 Operations rates Behavior and Appearance separately (plus Overall) Seeded; more can be added
2.3 Admin can add / rename / weight / deactivate criteria per team /performance/settings → Rating criteria
2.4 Criterion weights apply within their team only — they never let one team outvote another By design
2.5 One comment per team, independent of the stars Rating panel
2.6 A criterion that already holds ratings cannot be deleted, only deactivated Delete button disappears once used
2.7 Only assigned team members can rate /performance/settings → Rating teams
2.8 Export gains one column per active criterion Period tab → Export

1.3 Management analysis

# Requirement Where it lives
3.1 Trend over time, not a single snapshot — daily / weekly / monthly /performance → Analysis tab
3.2 Period-over-period comparison against the same-length window immediately before Delta chips under each KPI
3.3 Breakdown by zone, by partner, by rating team Three cards at the bottom
3.4 Band migration — how many drivers improved, held, declined Band migration card
3.5 When the two periods measured different components, the score delta is withheld with an explanation rather than shown as a misleading number Amber notice at the top
3.6 New performance.analyze permission, auto-granted to every role that already had performance.view Roles matrix

1.4 Supporting — Wrong Actions module

/wrong-actions was a non-functional stub; the conduct component had nothing to read. It is now a working module: list with KPIs, severity tabs, record/edit modal, detail page, delete, and a per-driver tab. Severity is weighted (Low 1, Medium 2, High 3), and incidents are scored against the Kuwait day they occurred, not the day they were filed.

2. How to test — Wrong Actions module (~10 min)

  1. Open Wrong Actions from the sidebar. Expect the seven KPI cards (Total Incidents, High Severity, Medium, Low, This Week, Weighted Total, Drivers Involved) and five tabs (All / High / Medium / Low / This week). On a fresh database the list shows “No incidents recorded”.
  2. Click Record incident. The modal opens with the title in the footer-left and the close X floating outside the top-right corner.
  3. Pick a driver using the search box — type a name, driver ID or employee ID. The dropdown shows the driver’s code, employee ID and zone beneath each name.
  4. Set Occurred at to a time yesterday. ✓ Try setting a future date — the picker should refuse it, and if forced the save returns “An incident cannot be dated in the future.”
  5. Pick a type (Delay / Zone breach / Hygiene failed / Uniform / Other) and a severity. ✓ The selected chip must turn green with a check; the helper text under severity must say “Counts as 3 toward the conduct allowance” for High, 2 for Medium, 1 for Low.
  6. Add details and Save. You land on the incident detail page and a success toast appears.
  7. Go back to the list. ✓ Total Incidents = 1, the matching severity KPI = 1, Weighted Total matches the severity weight (High → 3), Drivers Involved = 1.
  8. Record a second High-severity incident for the same driver. ✓ Weighted Total = 6, Drivers Involved stays 1, not 2.
  9. Click a row. ✓ It opens the detail page, not a modal. Confirm “Recorded by” shows your name and “Recorded” shows the filing time — separate from the “Occurred” time.
  10. From the detail page, click Edit, change the severity to Low, save. ✓ Weighted Total on the list drops accordingly.
  11. Click Delete, read the confirmation (“This removes the incident permanently and it stops counting against the driver”), confirm. ✓ The KPIs drop.
  12. Permission check: sign in as a role without wrong_actions.manage. ✓ The list is fully readable, but Record incident is disabled and rows have no Edit/Delete.
  13. Open Settings → Activity logs. ✓ Your create, edit and delete are all recorded.

3. How to test — Conduct feeding the score (~10 min)

  1. Record a High-severity incident for a driver who worked yesterday (check /attendance first — a driver who did not work has no denominator and will correctly score nothing).
  2. Open Performance → Settings. Under Compliance components, find Conduct. ✓ It is present and its weight is 0.
  3. Note the driver’s current Compliance % on the Period tab.
  4. Back in Settings, set Conduct’s weight to 1 and save. Note the three preview numbers side by side (old rule / saved / edited) before you save — they should differ once the weight is non-zero.
  5. Return to Performance → Period, set the date range to cover the incident date. Turn on the Components toggle.
  6. ✓ A Conduct column appears. The driver with the incident scores below 100%; drivers with no incidents score 100%.
  7. ✓ Their Compliance % has moved from step 3.
  8. ✓ Same-day check: the incident counts immediately, without waiting for the 02:00 rollup.
  9. Adjust Conduct allowance per worked day in Settings and confirm the score moves in the expected direction (a larger allowance is more forgiving).
  10. Reset Conduct’s weight to 0 when you are done, unless the client wants it live.

4. How to test — Component breakdown and SLA (~10 min)

  1. Performance → Period, date range = last 7 days. Turn on Components.
  2. ✓ One column per active component with a non-zero weight. Components at weight 0 do not get a column.
  3. ✓ Any cell showing — has a tooltip explaining the component was dropped and the rest re-weighted — not scored as zero. This matters: — and 0% mean opposite things.
  4. Click any driver row. ✓ The drilldown sheet shows the same component breakdown.
  5. Open Performance → Settings, change On-time SLA minutes, save, return to the list. ✓ The Within SLA component moves for drivers with deliveries in range.
  6. Open Attendance, pick a date with activity. ✓ Each row’s Compliance column expands to the per-day component scores, and they agree with the Performance page for the same day.
  7. Open any driver → Performance tab. ✓ Shows that driver’s band, fleet rank, component trend and rating history. The rank must be their rank across the whole fleet, not “1 of 1”.

5. How to test — Rating criteria (~10 min)

  1. Performance → Settings → Rating criteria. ✓ Operations shows Overall, Behavior, Appearance. Fleet and HR show Overall.
  2. Add a criterion to Operations — e.g. Communication, weight 1. ✓ It appears immediately.
  3. Performance → Settings → Rating teams. Add yourself to Operations.
  4. Go to Performance → Period, click a driver. ✓ The rating panel shows team sections, with a star row per criterion and one comment box per team.
  5. File a rating on each Operations criterion, then write a team comment. ✓ Saving a comment does not clear the stars, and changing a star does not clear the comment.
  6. ✓ The driver’s Rating column and Overall score both move.
  7. Return to Rating criteria. ✓ The criterion you just rated now shows a rating count and its Delete button is gone — only deactivate is offered. This is deliberate: deleting would erase filed reviews.
  8. Deactivate Communication. ✓ It disappears from the rating panel but the filed rating is preserved.
  9. Permission check: sign in as someone not on the Operations team. ✓ They can see Operations ratings but cannot edit them.
  10. Back on the Period tab, click Export. ✓ The workbook has a Rating column, one column per team, and one column per active criterion, with headers reading Operations · Behavior.

6. How to test — Analysis tab (~10 min)

Read section 8 before running this. The four range buttons currently show raw text keys instead of their labels. Everything else works.
  1. Performance → Analysis. The tab only appears for roles holding performance.analyze.
  2. Pick a range (the buttons are, left to right: Last 7 days, Last 30 days, This month, Last month) and a bucket (Daily / Weekly / Monthly).
  3. ✓ The line chart draws one line per measured component plus a black Overall line. Y-axis is 0–100. Hover shows values to one decimal.
  4. ✓ A component with no data anywhere in the window is absent from the legend entirely, rather than drawn as a flat empty line.
  5. ✓ Six KPIs: Avg component score, Drivers scored, Deliveries, Within SLA, Absent days, Conduct weight — each with a green/red/grey delta chip against the previous period.
  6. Switch to Last month. ✓ Expect the amber notice “The two periods measured different components”, and the Avg component score delta reads “Not comparable” instead of a number. This is the correct behaviour — July’s fleet events were pruned before retention was extended, so a July-vs-August speed comparison would be measuring the data, not the riders. The other five deltas still show, because they are raw counts that mean the same thing either way.
  7. ✓ Band migration card: current vs previous distribution bars, plus Improved / Held / Declined counts. The hint explains that only drivers scored in both periods can move.
  8. ✓ By zone / By partner / By rating team cards. Drivers with no zone or partner appear under Unassigned — they must not silently vanish.
  9. ✓ By rating team shows the measured score beside the average star that team gave, so you can see whether a team’s opinion tracks the numbers.
  10. Switch the bucket from Daily to Monthly. ✓ Fewer points, same shape.
  11. Permission check: sign in as a role without performance.analyze. ✓ The Analysis tab is not rendered at all.

7. How to test — Rollup and history (next day)

  1. The rollup runs at 02:00 Kuwait. The morning after any of the above, re-open the Analysis tab.
  2. ✓ Yesterday’s bucket is populated and matches what the Period tab showed for that date live.
  3. ✓ The newest bucket of a range ending today is not empty — today is read live rather than waiting for the rollup.

8. Known defect found while writing this guide

The four range buttons on the Analysis tab render as raw translation keys.

The panel asks for pages.performance.presets.last7, but the presets are stored one level deeper, under pages.performance.report.presets. With no message fallback, the buttons read the key path instead of “Last 7 days”. This affects both English and Arabic.

The buttons are fully functional — clicking them changes the range correctly — so this is cosmetic, but it is the first thing visible on the tab.

Fix (not yet applied): point the call at pages.performance.report.presets, or duplicate the four keys up one level in en.json and ar.json.

Pass / fail shorthand. A ✓ marks the expected result for that step. If the screen does not match, stop and note the driver, date range, and screenshot before continuing.
