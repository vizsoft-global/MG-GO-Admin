MG GO — Client note — 30 September 2026

Clear all data (as its own permission) and Vehicles as a full record

Audience: operations & compliance stakeholders  ·  Admin live on production  ·  Rider app screens built, Play Store build not published yet

1. What you requested

Bulk delete / Clear all data. Before go-live, and after a QA pass, you need to empty a whole module — not tick rows one by one — and it has to be impossible for someone who is only allowed to delete a single record. You asked for:

  • Its own permission on the Staff Access matrix, separate from Edit and Delete.
  • Nobody gets it by surprise — no existing user should gain it when we ship.
  • A count first, then a typed confirmation — never a single click.
  • Module by module: driver groups, companies, zones, vehicles, and so on.
  • It must also clean the files, not leave orphan photos in storage.

Vehicles. The Vehicles page was hard to work with:

  • The same vehicle could be identified by its plate or by a “bike ID”, depending on the page.
  • The list had one filter row and no counts — you could not see how many bikes or cars you run, or how many have no rider.
  • Opening a vehicle gave a thin page with a driver line. There was no way to see its documents, handovers, accidents or services.
  • There was no way to assign a rider from the fleet side, or to see and assign that rider’s assets.
  • Riders could not see any of it in the app.

2. What we delivered — Admin LIVE

2.1 Clear all data, as its own permission

  • A new tick on Staff Access: Bulk delete / Clear all data. The matrix now reads View data · Add data · Edit data · Delete individual records · Bulk delete / Clear all data.
  • Nothing was granted automatically. We checked production after the release: 22 module ticks exist in the permission catalogue, and 0 roles and 0 users hold any of them. You decide who gets it.
  • Delete one row still does not mean clear the table. Someone with Edit, Delete, or the older “manage” level cannot clear anything — there is no upgrade path from one to the other, by design.
  • 24 modules can be cleared, in a recommended order, covering deliveries, attendance, earnings, payouts, requests, visit bookings, notifications, e-signature, drivers, driver groups, vehicles, assets, fuel, restaurants, zones, partners, companies, delivery & incentive rules, wrong actions, document expiry, order reconciliation, DPD verifications and payroll. Rules and payouts reuse the Earnings tick, which is why they do not each add a separate one.
  • It tells you the number first. Opening Clear all shows the live row count, and if a module cannot be emptied yet it names the reason (“Deliveries still point at these rows”, “Restaurants still point at these rows”, “Fuel log rows still point at these vehicles”).
  • Typed confirmation. You must type the phrase (for example CLEAR 42 DRIVERS). The dialog states plainly that it is permanent and there is no undo.
  • Files are cleaned too. Storage objects are removed after the rows are gone, and clearing Drivers also removes the linked app logins.
  • Two places to do it: Settings → Data cleanup → Clear all data (all 24 modules, in order), and a Clear all button on the list page of each module that has one — drivers, deliveries, requests, visits, zones, partners, assets, fuel, notifications, document expiry, delivery rules, incentive rules, wrong actions and order reconciliation (the modules with no list of their own are cleared from the Settings screen).
  • Look, don’t touch: the page opens straight onto Clear all for someone who holds only a bulk-delete tick, so nobody sees row-by-row purge tools they cannot use.

2.2 Vehicles, as a record

  • One identity. The plate is now the unique Vehicle ID everywhere; the internal “bike ID” is only a slug alias. No screen can identify a vehicle two different ways again.
  • Counts on the list. A KPI strip shows Total, Unassigned, Bike, Car, Active and Replacement. Clicking a tile or picking the matching dropdown filters the same list, so the number you clicked and the rows you see always agree.
  • A real detail page. The same identity header the Drivers page uses — plate as the ID badge, then Chassis, Model, Year, Kind, Car type, Type of use, Fuel, Chip, Limit, Location, Owner, Replacement, Driver, MG ID, Phone and Project.
  • Assign a rider from the fleet side. A search box (name, MG ID or driver code — never a raw ID) assigns or unassigns on the spot, and a vehicle can only have one rider at a time.
  • Assets. The vehicle’s Assets tab lists the assigned rider’s assets and lets you Assign from the catalogue or Add a new asset; the Assignments tab under Assets gained its own Add button.
  • Companies popup is now a wide two-column dialog — fields on one side, live preview on the other, actions in the footer.

3. What we delivered — Rider app NEEDS PLAY UPDATE

  • The rider’s Vehicle tab now shows six more details (Chassis, Year, Condition, Car type, Type of use, Status) and five read-only history sections: Handover, Accident, Documents, Service, Assets — newest first, up to 20 entries each.
  • Each entry shows the date, what it was, and a note; where paperwork exists the row simply says File.
  • Riders see that a document exists, never where it is stored. No file paths and no private links ever reach the phone, and a rider can only ever read their own vehicle.
  • Old app versions are unaffected: the data was added, nothing was changed or removed.

Timing: the rider-app screens are written and on our branch, but the Play Store build has not been published — we will not push Play without your confirmation. Until that update reaches riders, the app keeps showing the current Vehicle tab. If a rider restarts on the old build, nothing breaks.

4. How to verify — Admin

  1. Staff Access. Sign in as super admin → Settings → Staff access. Scroll the module matrix: the fifth column reads Bulk delete / Clear all data, and it is off for every existing user. Confirm your own account is unaffected.
  2. The module list. Open Settings → Data cleanup → Clear all data. You should see the modules in order, each with a live row count and a Clear all button — and the note that it empties the module, not selected rows.
  3. Count and blockers. Find Zones. Its preview first reports how many rows would go. If drivers still have zones, the primary button stays disabled and the reason is printed. Repeat after clearing drivers — the block should lift.
  4. Typed confirmation. Open any module you intend to empty. The dialog shows the count and asks you to type the phrase (for example CLEAR 12 DRIVER GROUPS). Confirm anything else is refused, and that Cancel does nothing.
  5. Do one honest run. Clear a module you actually want emptied (driver groups or order reconciliation is the safest first). It should report the number cleared, and running it again should find nothing left.
  6. Files. After a clear that had attachments, open the storage browser for that module and confirm the files for those rows are gone, not just the rows.
  7. Do not look for it as a normal admin. Open the same page with an operator who has no bulk-delete tick: the Clear all tab/buttons are not offered, and the page refuses the action if it is called directly.
  8. Vehicles. /vehicles → the KPI strip counts match the list; click Unassigned and Bike and watch the rows narrow. Open a vehicle → the identity header shows the plate as the ID badge, the six-across field grid is filled, and Assign driver searches by name / MG ID / code and saves. Then check the Assets tab: the rider’s assets are listed, and Assign / Add asset both work.
  9. Companies popup. Settings → Companies → Edit opens a wide two-column dialog with the preview beside the fields and the buttons in the footer, with no inner scrollbar on a laptop screen.

5. How to verify — Rider app

This part needs an updated app build. On the rider’s phone, Play still has the previous version, so the new sections will not be visible until that update is published.

  1. Install the updated build on a test phone and sign in as a rider who has a vehicle assigned.
  2. Open Vehicle. Under the identity rows you should now see the six extra fields, then the five sections: Handover, Accident, Documents, Service, Assets.
  3. A rider with no history sees a friendly empty line in each section, not a blank card.
  4. Where a document exists, the row shows File — and there is no way to open or reveal the file itself, which is intended.
  5. Sign in as a rider with no vehicle assigned: no sections about someone else’s vehicle appear.
  6. Confirm Arabic still reads right-to-left and nothing overflows.

6. What did not change

  • Existing permissions, roles and sidebar layouts. The new tick starts off for everyone.
  • Nothing was deleted on production during this work — the counts shown are simply the live numbers.
  • Delivery, earnings, incentive and payroll rules are untouched.
  • The rider app keeps working on the current Play build.

Before you hand Clear all to anyone: decide the list of people who may use it, grant the tick per person in Staff access, and agree that a clear is run top to bottom. It is permanent and there is no undo.
